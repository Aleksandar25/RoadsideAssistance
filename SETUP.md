# Пускане на проекта на нов компютър

Стъпка по стъпка инструкции за клониране и пускане на приложението (backend + Android клиент) на компютър, различен от този, на който е разработвано.

## 1. Предварителни изисквания

Инсталирай следните програми, ако ги нямаш:

| Програма | Тествана версия | Къде да я вземеш |
|---|---|---|
| Node.js | v24.19.0 | nodejs.org |
| npm | 11.17.0 (идва с Node.js) | — |
| MongoDB (Community Server) | 8.3.x | mongodb.com/try/download/community |
| Android Studio | последна стабилна | developer.android.com/studio |
| Git | последна версия | git-scm.com |

При инсталацията на MongoDB избери опцията да се инсталира **като Windows услуга** — така върви на заден фон и не се налага ръчно стартиране всеки път.

## 2. Клониране на кода

Отвори терминал (PowerShell, Git Bash или терминала в Android Studio) и изпълни:

```
git clone https://github.com/Aleksandar25/RoadsideAssistance.git
cd RoadsideAssistance
```

## 3. Настройка на бекенда

```
cd backend
npm install
```

Копирай примерния конфигурационен файл:

```
copy .env.example .env
```

(на Mac/Linux: `cp .env.example .env`)

Отвори новосъздадения `.env` и провери/попълни стойностите:

```
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb://127.0.0.1:27017/roadside_assistance
JWT_SECRET=<дълъг случаен низ — може да измислиш нов, или да копираш стария>
JWT_EXPIRES_IN=7d
```

`MONGO_URI` по-горе сочи към локална MongoDB инстанция — ако MongoDB услугата е инсталирана и работи на новия компютър, не трябва да променяш нищо тук.

### Стартиране на бекенда

```
npm run dev
```

Ако всичко е наред, в конзолата ще видиш съобщение, че сървърът слуша на порт 5000 и има връзка с MongoDB.

### Проверка

Отвори нов терминал (остави предишния да върви) и изпълни:

```
curl http://localhost:5000/api/health
```

Очакван резултат: JSON отговор с код 200 (не грешка на връзката).

### (По избор) Пускане на автоматизираните тестове

```
npm test
```

Очакван резултат: `Tests: 24 passed, 24 total`.

## 4. Настройка на Android клиента

Отвори Android Studio → **Open** → избери папката `android/` от клонирания repo.

Изчакай Gradle sync-а да завърши (Android Studio автоматично ще генерира `local.properties` с правилния `sdk.dir` за твоя компютър).

Отвори файла `android/local.properties` и добави в края (ако вече го няма):

```
MAPS_API_KEY=AIzaSyCxP6yn-qzkJ00UDGeQhLmhjXO-KhbxCho
```

**Важно:** този файл е в `.gitignore` — не идва от GitHub, трябва да се добави ръчно на всеки нов компютър.

### Проверка на Google Maps API ключа (SHA-1)

Google Maps API ключовете обикновено са ограничени по SHA-1 отпечатък на сертификата, с който е подписано приложението. Всяка нова инсталация на Android Studio генерира различен debug keystore → различен SHA-1. Ако след пускане на приложението картата не се показва (вместо нея излиза текстово съобщение):

1. В Android Studio: десен панел **Gradle** → `RoadsideAssistance` → `app` → `Tasks` → `android` → двоен клик на `signingReport`.
2. В долния прозорец **Run** ще се изпише SHA-1 отпечатък за `debug` конфигурацията — копирай го.
3. Отиди на [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials → намери ключа `AIzaSyCxP6yn-qzkJ00UDGeQhLmhjXO-KhbxCho` → в ограниченията по приложение добави новия SHA-1 (заедно със стария, не го трий, за да работи и на предишния компютър).

### Пускане на приложението

1. Увери се, че бекендът от стъпка 3 работи (в отделен терминал).
2. В Android Studio създай/избери Android емулатор (AVD Manager → напр. Pixel 8, API 35).
3. Натисни зеления бутон **Run ▶** (не "Build/Make" — той само компилира, не инсталира и пуска).

Приложението трябва да стартира на емулатора с екран за вход.

### Адресът на бекенда (важен детайл)

Файлът `android/app/src/main/java/com/diploma/roadsideassistance/core/Constants.kt` съдържа:

```kotlin
const val BASE_URL = "http://10.0.2.2:5000/"
```

`10.0.2.2` е специален адрес, през който Android **емулаторът** вижда `localhost` на компютъра, на който работи самият той.

- Ако бекендът и емулаторът са на **един и същ** компютър → работи автоматично, без промяна.
- Ако искаш да тестваш на **реално устройство** (телефон) или бекендът е на друг компютър в мрежата → трябва да смениш `BASE_URL` с реалния LAN IP на машината с бекенда, напр.:
  ```kotlin
  const val BASE_URL = "http://192.168.1.50:5000/"
  ```
  (телефонът и компютърът трябва да са в една и съща WiFi мрежа), после да пресъздадеш (rebuild) приложението.

## 5. Тестови акаунти

От предишни тестове в базата вероятно вече има потребители, ако копираш реалната база данни. За чисто нова база данни трябва сам да регистрираш нов CLIENT и нов PROVIDER акаунт през екрана за регистрация в приложението, преди да можеш да тестваш пълния сценарий (заявка → приемане → изпълнение → оценка).

## 6. Чести проблеми

| Проблем | Причина | Решение |
|---|---|---|
| Бекендът не стартира, грешка за връзка с MongoDB | MongoDB услугата не работи | Провери в Services (Windows) дали "MongoDB" услугата е Running |
| Картата не се показва в приложението | Липсващ или неоторизиран `MAPS_API_KEY` | Виж раздел "Проверка на Google Maps API ключа" по-горе |
| Старо поведение след промяна в кода | Стар инсталиран APK на емулатора | `adb uninstall com.diploma.roadsideassistance`, после Run отново |
| `npm install` спира с грешки | Несъвместима версия на Node.js | Провери с `node -v`, сравни с v24.19.0 |
